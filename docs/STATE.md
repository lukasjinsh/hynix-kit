# 진행 단계 (STATE)

단계가 바뀔 때마다 갱신하고 커밋한다. 전환 전 세 가지 확인: 드리프트 없나 / 증거 없는 체크 없나 / 너무 순조롭지 않나.

| 단계 | 목표 시각 | 상태 | 증거 |
| --- | --- | --- | --- |
| 1. 발굴 | ~10:15 | ☐ | 실무자 DM 인터뷰 5~7문 |
| 2. 서면합의 | ~10:25 | ☐ | docs/AGREEMENT.md + 첫 커밋 |
| 3. 스캐폴딩 | ~10:40 | ☐ | 빈 앱 실행, Browser 도구에서 확인 |
| 4. E2E v0 | ~11:50 | ☐ | 입력→처리→출력 경로 1개 동작 |
| 5. 중간검증 | ~12:20 | ☐ | 테스트 통과 로그, 리뷰 세션 지적 반영 커밋 |
| 6. 수용확인 | ~12:40 | ☐ | 실무자 피드백 1회 반영, 문서 3종 |
| 7. 제출 | 12:50 | ☐ | 제출 ID 확인 |
